# Plan: Fix F-Droid Reproducible Build Verification Failure

## Problem

F-Droid build verification fails with `APK Signature Scheme v3: CHUNKED_SHA256 digest mismatch` when comparing the reference binary (from GitHub releases) against the F-Droid-built APK.

## Root Cause Chain

1. `writer.go:create()` uses 4-byte alignment for ALL files, including `.so` → `.so` lands at offset 16368 (not 16384)
2. `writer.go:Close()` always writes META-INF (debug signing), even for release builds
3. F-Droid recipe uses `zip -d crocson.apk "META-INF/*"` to remove debug META-INF
4. `zip -d` rewrites ALL local file headers, destroying any alignment fix applied by `writer.go:create()`
5. CI uses `apksigner sign` which re-aligns `.so` to 16384 → mismatch with F-Droid

Previous fix to `release.go:zipAlign()` didn't help because `fyne package --release` never calls `zipAlign()`.

Previous fix to `writer.go:create()` (16KB alignment) is correct but gets undone by `zip -d`.

## CI Flow (from fyne.yml)

```
fyne package -os android/arm --release     # writer.go: APK + 16KB .so + META-INF debug + data descriptors
zip -d crocson.apk "META-INF/*" --out crocson-arm.apk  # removes META-INF + data descriptors
apksigner sign --ks ... crocson-arm.apk    # adds META-INF/CROC.* + signing block (NO alignment!)
```

Key: `apksigner` does **NOT** align. Official docs say "use zipalign BEFORE apksigner".
The `fyne package --release` also does NOT call `zipAlign()` — that's only in `fyne release`
(`releaseAction` → `afterPackage`). `fyne package` calls `packageAndroid` → `goAndroidBuild(release=true)`.

## Root Cause (revised)

1. **Data descriptors** — Go `archive/zip` writes data descriptors (flag 0x08).
   `zip -d` removes them by rewriting entries with filled-in sizes. Both CI and F-Droid.

2. **16KB alignment** — `writer.go:120` sets 16KB .so alignment.
   `zip -d` on F-Droid breaks it (16368 instead of 16384).
   CI APK has correct 16384 — possibly because Ubuntu `zip -d --out` preserves alignment.
   CI uses `--out` flag; our recipe didn't.

## Fix: `zip -d --out` + SDK `zipalign` (matching CI flow exactly)

### Build #4 result (zipalign.py approach)
- Build succeeded, zipalign.py ran OK
- F-Droid has `build-tools/31.0.0` (from `ls $$SDK$$/build-tools/`)
- v3 still FAILED: CD extra mismatch (CI=1, FD=3977)
- `zipalign.py` preserved CD extra from `zip -d` (without `--out`) → wrong CD extra

### Root cause: CD extra differs
| APK | .so data_at | local_extra | CD_extra | Match? |
|-----|-------------|-------------|----------|--------|
| CI reference | 16384 | 3973 | **1** | baseline |
| FD-old (zip -d --out) | 16368 | 3957 | **1** | CD ✓, align ✗ |
| FD-new3 (no zip -d) | 16384 | 3957 | 3977 | CD ✗, data_desc ✗ |
| FD-zipalignpy (zip -d + zipalign.py) | 16384 | 3973 | **3977** | CD ✗ |

`zip -d` with `--out` → CD_extra=1 (matches CI)
`zip -d` without `--out` → CD_extra matches local_extra (3957→3977 via zipalign.py)
`zipalign.py` preserves input CD extra → doesn't fix the mismatch

SDK `zipalign` only modifies local header extra + updates CD offsets, **preserves CD extra**.

### Proposed: mirror CI exactly + fix alignment with SDK zipalign

**Build #5 fix**: `zipalign` in build-tools/31.0.0 does NOT support `-P` flag. Use `-p` instead.

```yaml
    build:
      ...
      - fyne package -os android/${ABI} --release
      - zip -d crocson.apk 'META-INF/*' --out crocson-${ABI}.apk
      - $$SDK$$/build-tools/$$(ls $$SDK$$/build-tools/ | sort -V | tail -1)/zipalign -f -p 4 crocson-${ABI}.apk crocson-aligned.apk
      - mv crocson-aligned.apk crocson-${ABI}.apk
```

`zipalign` usage (build-tools/31.0.0):
```
zipalign [-f] [-p] [-v] [-z] <align> infile.zip outfile.zip
  -p: page-align uncompressed .so files
```

Why this works:
1. `zip -d --out` → CD_extra=1 (same as CI), data descriptors removed ✓
2. writer.go already produces 16KB-aligned .so files, `zip -d --out` preserves alignment ✓
3. `zipalign -f -p 4` → safety net, page-aligns .so (4KB), preserves CD_extra=1
4. Result: CD_extra=1 ✓, data_at=16384 ✓ — matches CI APK structure

No `reproducible-apk-tools` srclib needed. Dynamic version detection via `$(ls ... | sort -V | tail -1)`.

### Build #5 result: zipalign still causes mismatch

- Build succeeded, zipalign `-p` worked (no `-P` flag error)
- v3 STILL FAILED: CHUNKED_SHA256 digest mismatch
- `diff -r` between extracted APKs showed "Unexpected diff output" — content differs

**Root cause**: `zipalign` modifies the APK structure (rewrites extra fields, changes padding).
CI flow has NO `zipalign` step: `fyne package → zip -d --out → apksigner sign`.
Adding `zipalign` introduces structural differences that break byte-for-byte matching.

**Fix**: Remove `zipalign` entirely. Since `writer.go` already produces 16KB-aligned .so files
and `zip -d --out` preserves alignment, `zipalign` is unnecessary.

### Build #6 plan: fix CD_extra with Go tool from tools repo + remove zipalign

**Root cause confirmed**: All binary content is identical (SHA256 matches).
Only difference is CD_extra size for .so: CI=1 byte (0x00), FD=3977 bytes (0x00×3977).
All other CD_extra values match (classes.dex=3, icon.png=0, resources.arsc=1, AndroidManifest.xml=3).

Debian trixie `zip -d` copies local_extra → CD_extra (+4 bytes), Ubuntu `zip -d` writes minimal CD_extra.

**Fix**: After `zip -d --out`, run `fix-cd-extra` tool from tools repo to patch CD_extra for .so from 3977→1.
Remove `zipalign` (it changes local_extra unnecessarily — build #4 had correct local_extra).

Steps:
1. Write `cmd/fix-cd-extra/main.go` in crocson repo
2. Test locally on CI reference APK
3. Commit, push to crocson
4. Edit `generate_recipe.sh`: remove zipalign+mv, add `cd cmd/fix-cd-extra && go run . <apk> && cd -`
5. Run `bash metadata/generate_recipe.sh`
6. Push recipe
7. Trigger F-Droid build

Recipe build commands (relevant part):
```yaml
      - fyne package -os android/${ABI} --release
      - zip -d crocson.apk 'META-INF/*' --out crocson-${ABI}.apk
      - cd cmd/fix-cd-extra
      - go run . ../../crocson-${ABI}.apk
      - cd -
```

**Why `cd` + `../../` path**:
`go run ./cmd/fix-cd-extra` from root won't work — go.mod in root causes
module resolution issues. Must `cd` into `cmd/fix-cd-extra/` first.
From there, the APK is at `../../crocson-${ABI}.apk` (root → cmd → fix-cd-extra,
so two levels up). F-Droid joins build steps with `;`, so `cd` persists.

### Problem: CI and FD must use identical pipeline

CI: `fyne package` → `zip -d --out` → `apksigner sign` (no zipalign)
FD: `fyne package` → `zip -d --out` → `zipalign -p 4` → `apksigcopier`

zipalign changes `local_extra` (3973→3969), so CI2 won't match FD after zipalign.
**Both sides need zipalign**, or neither.
