# Дедупликация вкладок локально (localStorage-счётчик), без рассылки close

## Суть

Убрать серверную рассылку `{"cmd":"close"}` для дедупликации вкладок отправителя. Вместо этого — **локальный счётчик в localStorage** в самом `directory.html`. localStorage изолирован по браузеру/origin → у отправителя и получателя независимые счётчики, поэтому они не влияют друг на друга. Симметрично и бесплатно.

### Семантика: какой таб закрывать

При клике/открытии приложение открывает **новый** таб (часто с другим путём — подпапка). Значит «выживить» должен **новый** таб, а **старые** закрываются. Поэтому:

- Каждый таб при загрузке увеличивает монотонный счётчик в localStorage и запоминает своё значение `myN`.
- Слушаем `storage`: если другой таб записал значение **больше `myN`** (пришёл новее таб) — этот (старый) таб закрывает сам себя `window.close()`.

Почему сравнение `newValue > myN`, а не буквально «>1»: это надёжно выделяет именно старые табы и не требует декремента при закрытии (декремент при `pagehide` ненадёжен и ломает относительное сравнение). Счётчик монотонно растёт — это безопасно (число не переполнится, относительный порядок корректен).

> Если всё же нужно, чтобы закрывался **новый** таб (self-close при «уже есть вкладка»), скажите — логику легко перевернуть, но тогда при открытии подпапки пользователь останется на старом (чужом) содержимом.

## Изменения

### 1. `directory.html` — локальный счётчик вкладок

Добавить (в основном `<script>`, рядом с инициализацией `currentUserId`, ~стр. 337):

```js
// --- Дедупликация: один таб на браузер (localStorage изолирован по origin) ---
(function () {
    var KEY = 'dirTabs';
    var myN = parseInt(localStorage.getItem(KEY) || '0', 10) + 1;
    localStorage.setItem(KEY, String(myN));
    // Пришёл новее таб (счётчик стал больше моего) → закрыть этот старый таб.
    window.addEventListener('storage', function (e) {
        if (e.key === KEY && parseInt(e.newValue || '0', 10) > myN) {
            window.close();
        }
    });
})();
```

Примечания:
- Событие `storage` не срабатывает в записавшем документе → новый таб себя не закрывает. ✓
- Срабатывает в остальных табах того же origin → закрываются старые. ✓
- Получатель — другой браузер/машина/origin → его localStorage и счётчик независимы → не затрагивается. ✓
- Действует для **любого** таба с `directory.html` (в т.ч. открытого вручную). Ключ `dirTabs` уникален, видеозвонки (`videocall.html`) не задействованы.

### 2. `send.go` — убрать серверную рассылку close для дедупликации

- send.go:641-643 — удалить блок:
  ```go
  if uid == webdavURL.String() {
      broadcastClose(nil)
  }
  ```
  (Открытие URL ниже по потоку остаётся без изменений — дедуп делает браузер.)
- send.go:735 — удалить строку `broadcastClose(nil)` (оставить лог и `OpenURL(chatURL)`).

### 3. Без изменений

- `broadcastClose` (WS → всем) **остаётся** и используется только для:
  - остановки сервера `WebDAVServer.Stop()` (webdav.go:543);
  - закрытия приложения `cleanup()` (main.go:459).
  Там действительно нужно закрыть **все** табы (включая получателя), т.к. сервер/приложение выключается.
- recv.go — изменений не требуется: счётчик в `directory.html` работает у получателя автоматически (его браузер).
- Команда `{"cmd":"close"}` и обработка `window.close()` в WS-обработчике `directory.html` — без изменений.

## Что получается

| Сценарий | Кто закрывает | На кого влияет |
|---|---|---|
| Клик по корню / авто-открытие (send.go) | браузер, localStorage | только табы **этого** браузера |
| Остановка сервера / выход из приложения | `broadcastClose` (WS) | **все** табы (корректно) |

## Проверка

- `go build ./...` / `go vet ./...`.
- Сценарий: отправитель открыл таб → получатель подключился через туннель (свой таб) → отправитель кликает корень → старый таб отправителя закрывается, таб получателя остаётся живым; открывается свежий таб отправителя.
- Граничный случай (редкий): два таба открыты строго одновременно — возможна гонка (оба прочитают одно значение). На практике приложение открывает табы последовательно, поэтому маловероятно.
