# Plan: Move syso tool dependencies to a separate Go module

## Problem

When `cmd/syso` was added, its dependencies were pulled into the root `go.mod`:
- `github.com/Kodeworks/golang-image-ico` (direct) — PNG to ICO conversion
- `github.com/josephspurrier/goversioninfo` (direct) — Windows version info / .syso generation
- `github.com/akavel/rsrc` (indirect) — transitive dep of goversioninfo

These are **only** used by `cmd/syso/main.go` and not by any other package in the project.

## Solution

Create a **separate Go module** in `cmd/syso/` so these dependencies live only there.

### Steps

1. **Create `cmd/syso/go.mod`** with its own module declaration and the needed dependencies:
   - `github.com/Kodeworks/golang-image-ico`
   - `github.com/josephspurrier/goversioninfo`
   - `github.com/BurntSushi/toml` (also used in main module's `about.go`, so stays in both)

2. **Run `go mod tidy` in `cmd/syso/`** to resolve and generate `go.sum` there.

3. **Remove from root `go.mod`**:
   - `github.com/Kodeworks/golang-image-ico` from direct `require`
   - `github.com/josephspurrier/goversioninfo` from direct `require`
   - `github.com/akavel/rsrc` from indirect `require`

4. **Run `go mod tidy` in root** to clean up.

5. **Verify**: `go build ./...` and `go run ./cmd/syso` both work.

### What stays in root go.mod

`github.com/BurntSushi/toml` — used by `about.go` in the main module.

### Files changed

- **New**: `cmd/syso/go.mod`, `cmd/syso/go.sum`
- **Modified**: `go.mod`, `go.sum` (dependencies removed)
