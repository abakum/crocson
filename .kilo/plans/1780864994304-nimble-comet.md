# Plan: Fix window icon and taskbar icon on Linux/X11

## Problem
1. **Window title bar**: no app icon (blank/default)
2. **Taskbar/panel shortcut**: shows default (generic) icon instead of the crocson icon

The `.desktop` file and `pixmaps` icon are already installed (tag search works), but the WM cannot properly match the window to the `.desktop` entry.

## Root cause

### Taskbar icon — missing `StartupWMClass`
GLFW (used by Fyne) does NOT set `glfw.X11ClassName` / `glfw.X11InstanceName` window hints. Fyne also doesn't set them. So on X11, `WM_CLASS` defaults to the binary name: **`crocson`**.

The `.desktop` file is named `com.github.abakum.crocson.desktop` — the WM can't match `WM_CLASS=crocson` to this file without a `StartupWMClass` hint.

### Icon only in `pixmaps` — not in icon theme
The icon is installed to `~/.local/share/pixmaps/` (legacy). Modern WMs/DEs prefer the XDG icon theme structure at `~/.local/share/icons/hicolor/<size>/apps/`. GNOME in particular often ignores `pixmaps`.

### No app-level icon set
`a.SetIcon()` is never called in `main()`. Fyne's `App.Icon()` returns nil, so system tray and other fallbacks use the default icon.

## Changes

### 1. Modify: `install_desktop_linux.go`

#### a) Add `StartupWMClass=crocson` to generated `.desktop`

```go
desktop += "StartupWMClass=crocson\n"
```

Add this line after `Icon=` and before `Comment=` (or anywhere in the main section).

The value `crocson` matches what GLFW sets as `WM_CLASS` (the binary name from `argv[0]`).

#### b) Replace pixmaps install with hicolor icon theme dir

Remove the pixmaps install block. Instead, install to the XDG icon theme directory:

```go
iconsDir := filepath.Join(xdg.DataHome, "icons", "hicolor", "512x512", "apps")
iconPath := filepath.Join(iconsDir, appID+".png")
if _, err := os.Stat(iconPath); err != nil {
    if err := os.MkdirAll(iconsDir, 0755); err != nil { ... }
    if err := os.WriteFile(iconPath, iconData, 0644); err != nil { ... }
}
```

Remove old pixmaps icon if it exists:

```go
oldIcon := filepath.Join(xdg.DataHome, "pixmaps", appID+".png")
os.Remove(oldIcon)
```

#### c) Run `gtk-update-icon-cache` after installing icons

```go
if p, err := exec.LookPath("gtk-update-icon-cache"); err == nil {
    _ = exec.Command(p, filepath.Join(xdg.DataHome, "icons", "hicolor"), "-f").Run()
}
```

Add this after writing the icon, before writing `.desktop`.

#### d) Keep simple `.desktop` existence check

No changes to the early-return logic — just check if `.desktop` exists. The old file (without `StartupWMClass`) will be deleted manually once before the first run with the new code:

```bash
rm -f ~/.local/share/applications/com.github.abakum.crocson.desktop
```

No `"bytes"` import needed.

### 2. Modify: `main.go`

Replace `w.SetIcon()` with `a.SetIcon()`, called **before** `a.NewWindow()`:

```go
a := app.NewWithID(ID)
a.SetIcon(fyne.NewStaticResource("Icon.png", iconData))
```

And **remove** line 313:
```go
// DELETE this line — now redundant:
w.SetIcon(fyne.NewStaticResource("Icon.png", iconData))
```

When `a.NewWindow(CS)` is called, Fyne internally does `ret.SetIcon(ret.icon)` where `ret.icon == nil`. `SetIcon(nil)` falls back to `fyne.CurrentApp().Icon()`, which returns the icon we just set. So the window automatically gets the app icon — no separate `w.SetIcon()` needed.

The app-level icon is cross-platform and used by:
- Window icon via fallback in `createWindow()` → `ret.SetIcon(nil)` → `a.Icon()`
- Fyne's system tray fallback (`fyne.CurrentApp().Icon()`)
- Fyne's about dialog
- macOS Dock icon
- Windows taskbar icon
No build-tag guard needed — call is safe on all platforms.
