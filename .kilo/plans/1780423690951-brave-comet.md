# План: Исправление воспроизводимости сборки F-Droid

## Проблема

Сборка на F-Droid не воспроизводима — APK, собранный на F-Droid, отличается от референсного бинарника (APK из GitHub Releases). Отличаются:
- `AndroidManifest.xml`
- `classes.dex`
- `classes2.dex`

Ошибка: `APK Signature Scheme v3 signer #1: APK integrity check failed. CHUNKED_SHA256 digest mismatch.`

## Диагноз

### 1. Разные JDK — ГЛАВНАЯ ПРИЧИНА различия в `classes2.dex`

В вашем `AndroidManifest.xml` объявлен сервис:
```xml
<service android:name=".CrocsonService" android:foregroundServiceType="dataSync" />
```

Fyne CLI при сборке APK компилирует Java-класс этого сервиса через `javac` + `d8`:
- `build_androidapp.go:188` → `compileJavaServices(manifestData, dir)`
- `build_androidapp.go:530` → `exec.Command("javac", "-source", "1.8", "-target", "1.8", ...)`
- `build_androidapp.go:569` → `exec.Command(d8Path, "--output", dexOut, ...)`

Результат записывается в `classes2.dex`. А `d8` (dex compiler) из Android SDK build-tools **зависит от JDK**, под которым работает.

| Окружение | JDK | Версия |
|---|---|---|
| **CI (GitHub Actions)** | Temurin JDK 21 | `actions/setup-java@v4` с `distribution: 'temurin'` |
| **F-Droid** | OpenJDK 21 (Debian Trixie) | `21.0.11+10-1~deb13u2` |

Разные дистрибутивы JDK дают **разный Java-байт-код**, который после `d8` даёт **разный dex-файл** → `classes2.dex` не совпадает.

### 2. ZIP timestamps — причина различия `AndroidManifest.xml` и остальных ZIP entries

В `writer.go:139` fyne CLI создаёт ZIP-записи без явного `Modified`:
```go
zipfw, err := w.w.CreateHeader(&zip.FileHeader{
    Name:  name,
    Extra: make([]byte, extra),
})
```

Go по умолчанию ставит **текущее время** в `Modified`. Разное время сборки → разные timestamps в ZIP entries → `AndroidManifest.xml` (и все файлы в APK) бинарно отличаются.

### 3. `classes.dex` (встроенный) — тоже должен совпадать

`classes.dex` — это встроенный dex-файл (base64-константа в `dex.go`). Он одинаковый в обеих сборках. Однако ZIP-entry timestamp для `classes.dex` отличается по причине #2, что тоже влияет на верификацию подписи v3.

## Что совпадает (проверено)

- **Go**: `go1.25.0` в обоих случаях
- **Fyne CLI**: один и тот же коммит `abakum/tools` (генератор рецепта берёт последний)
- **fyne.io/fyne/v2**: `v2.7.0` (в tools), `v2.7.4` (в crocson) — одинаково
- **Android SDK**: `platforms;android-36`, `build-tools;36.0.0`
- **NDK**: `r27d`

## Решение

### Вариант A: Привести CI к окружению F-Droid (рекомендуется)

F-Droid не позволяет контролировать JDK извне — он использует свой buildenv. Поэтому нужно, чтобы **CI использовал тот же JDK**, что и F-Droid.

**Изменение в `.github/workflows/fyne.yml`** (job `build-android`):

Заменить:
```yaml
- name: Set up JDK 21
  uses: actions/setup-java@v4
  with:
    java-version: '21'
    distribution: 'temurin'
```
на:
```yaml
- name: Set up JDK 21
  run: |
    sudo apt-get update
    sudo apt-get install -y openjdk-21-jdk-headless
    sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
    echo "JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64" >> $GITHUB_ENV
```

Это обеспечит тот же OpenJDK 21, что и на F-Droid (Debian Trixie). Но точная версия пакета может различаться между Ubuntu (GitHub Actions runner) и Debian Trixie (F-Droid). Нужна проверка.

**Альтернатива**: использовать Docker-контейнер Debian Trixie в CI для полного совпадения окружения.

### Вариант B: Удалить `<service>` из AndroidManifest.xml

Если сервис `CrocsonService` можно переместить в Go-код (или убрать на время), то `compileJavaServices` вернёт `nil` и `classes2.dex` не будет создан. Это убирает зависимость от JDK.

### Вариант C: Использовать `Antivirus: true` в F-Droid metadata

F-Droid поддерживает `Antivirus: true` для пропуска проверки воспроизводимости, но это не рекомендуется.

### Обязательное дополнение: Очистка ZIP timestamps

Fyne CLI (`writer.go:139`) создаёт ZIP-записи без `Modified` → Go ставит текущее время.

**Решение**: Патч `writer.go` в `abakum/tools` — одна строка:

```go
// в функции create(), строка ~139
zipfw, err := w.w.CreateHeader(&zip.FileHeader{
    Name:     name,
    Extra:    make([]byte, extra),
    Modified: time.Time{},  // нулевой timestamp — воспроизводимость
})
```

Альтернатива — постобработка APK скриптом после `fyne package`, но патч fyne надёжнее.

## План реализации

### ~~Шаг 1: Патч `writer.go` в `abakum/tools`~~ — ВЫПОЛНЕНО
- Добавлен `Modified: time.Time{}` в `CreateHeader` вызов
- Запушен, обновлён srclib в F-Droid

### Шаг 2: Установить OpenJDK 21 + Android SDK 36 локально (Debian 12)

```bash
# JDK 21
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk-headless
sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64

# Android SDK 36
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "platforms;android-36" "build-tools;36.0.0"
```

### Шаг 3: Привести JDK в CI к F-Droid
Заменить в `.github/workflows/fyne.yml` (строки 529-534):

**Было:**
```yaml
      # Step 6.3: Set up JDK 21
      - name: Set up JDK 21
        uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'
```

**Станет:**
```yaml
      # Step 6.3: Set up JDK 21
      - name: Set up JDK 21
        run: |
          sudo apt-get update
          sudo apt-get install -y openjdk-21-jdk-headless
          sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
          echo "JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64" >> $GITHUB_ENV
```

### Шаг 4: Обновить F-Droid metadata — ВЫПОЛНЕНО
- srclib `abakum-fyne-tools` обновлён на коммит с патчем `writer.go`

### Шаг 5: Пересобрать и проверить
- Запустить workflow `fyne.yml` в CI для android
- Выложить APK в Release
- Запустить сборку на F-Droid и сравнить
